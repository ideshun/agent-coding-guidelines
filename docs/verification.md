# 验证与验收

## 维护检查

运行以下命令需要已有 Node.js 20+，仅用于维护仓库，不是安装技能的前提；不安装依赖、不调用模型、不读取账号或原始配置。

```sh
node --test tests/*.test.mjs
node scripts/validate.mjs
```

测试验证公开任务、部分行为 oracle、记录格式、公平对照门槛、拒绝覆盖结果、指纹、兼容目录结构、轻量导出保持根正文、完整导出保持源参考正文及失效引用处理。验证器检查技能身份、额外可发现入口、链接、空文件、文本预算和部分敏感模式；接受标准可选字段，不用固定标题、语言或等级关键词推断语义完整性。

根入口 70 行 / 6000 字节、参考文件 45 行是本仓库维护预算，不是 Agent Skills 标准或 token 计量。当前 frontmatter 的 description 使用 JSON 兼容的双引号 YAML 标量；脚本检查的是仓库结构和有限标量模式，不是完整 YAML 解析器。标准格式需另外使用 Agent Skills 校验器核对；规则语义、触发边界和授权关系仍需人工审查及行为验收。模式检查也不能证明没有所有秘密。

## 原生安装验收

按 README 和兼容目录确认产品、端型、版本、执行端及作用域。原生 Skills 安装根 SKILL.md、LICENSE 与 `references/{clarify,plan,verify}.md`，和源文件逐字比对；原生导入要确认完成导入且参考文件可读取；规则型入口与同一源的 instructions 导出比对，并保留原生元数据。按宿主机制刷新，在技能列表、诊断接口或规则附件中确认实际入口与启用状态。文件存在不等于原生发现；仅“看到了技能”不等于适当选择或更好的模型行为。安装器注册表声明路径不等于厂商功能确认，88 个宿主目录不等于 88 个已运行验证的客户端。

用合成任务开启独立新会话，不在提示里点名技能；在可观测时记录实际选择、读取、diff、检查结果。若把技能正文直接注入提示，应标记为正文行为测试，不能冒充隐式选择验收。模型调用遵循用户已有授权和预算，不因维护命令自动调用。

## 行为与成本

[八类公开基准](benchmarks.md)覆盖样式、React、类型、bug、跨文件、设计、关键歧义与严格范围；[多语言验收](multilingual-evaluation.md)覆盖简体、繁体、英文、中英混输及非代码负例。

固定模型、宿主、能力、预算、任务事实与可控的全局规则，比较无新增规则、历史规则及新规则。同一任务每组至少三个独立重复；这个最低复现要求不等于统计显著性。控制不了既有插件或全局指令时，明确标记对照未隔离，不发布“更准”或“更省”的泛化结论。

优先审查完成与质量，再比较真实 input/output/total、工具调用、时间和确认次数。缺测为 null，不从字符数推算账单。不用关键词出现次数冒充设计质量、中文理解或审查正确性。

## 当前证据

本仓库提供可复现框架与验收规范，没有可发布的受控模型对照成绩。历史旧正文的少量本机 smoke 不能证明当前正文改善了模糊目标处理；原生发现、自动选择、行为表现与成本各自记录。具体已执行的本机证据及路径留在忽略目录，不作为公共原始配置上传。
