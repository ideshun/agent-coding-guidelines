# 验证与验收

## 维护检查

运行以下命令需要已有 Node.js 20+，仅用于维护仓库，不是安装技能的前提；不安装依赖、不调用模型、不读取账号或原始配置。

```sh
node --test tests/*.test.mjs
node scripts/validate.mjs
```

测试验证 skill 身份与 frontmatter、目录记录格式、正文转换完整性及有限公开文件检查。验证器检查 skill 身份、frontmatter、链接、部分敏感模式。模式检查不能证明没有所有秘密。

## 原生安装验收

按 README 和兼容目录确认产品、端型、版本、执行端及作用域。原生 Skills 安装各 `skills/<name>/SKILL.md` 与 `LICENSE`，和源文件逐字比对；原生导入要确认完成导入且文件可读取；规则型入口与同一源的 instructions 导出比对，并保留原生元数据。按宿主机制刷新，在技能列表、诊断接口或规则附件中确认实际入口与启用状态。文件存在不等于原生发现；仅「看到了技能」不等于适当选择或更好的模型行为。安装器注册表声明路径不等于厂商功能确认，88 个宿主目录不等于 88 个已运行验证的客户端。

用合成任务开启独立新会话，不在提示里点名技能；在可观测时记录实际选择、读取、diff、检查结果。若把技能正文直接注入提示，应标记为正文行为测试，不能冒充隐式选择验收。模型调用遵循用户已有授权和预算，不因维护命令自动调用。

## 行为与成本

宿主发现与行为验收分开验证。若未来做对照评估：固定模型、宿主、能力、预算、任务事实与可控的全局规则，比较无新增规则、历史规则及新规则；同一任务至少三个独立重复，这个最低复现要求不等于统计显著性。控制不了既有插件或全局指令时，明确标记对照未隔离，不发布「更准」或「更省」的泛化结论。缺测为 null，不从字符数推算账单；不用关键词出现次数冒充设计质量、中文理解或审查正确性。

## 当前证据

本仓库提供可复现的验收规范，没有可发布的受控模型对照成绩。静态测试通过不能证明当前正文改善了模糊目标处理；原生发现、自动选择、行为表现与成本各自记录。具体已执行的本机证据及路径留在忽略目录，不作为公共原始配置上传。
