# 规则 → 探针清单（探索性）

本文件记录当前正文与八类公开 fixture 的对应关系，用于发现覆盖缺口和候选冗余。标注为**探索性**：未调用模型，未跑 `none` / `new` 对照矩阵，不作统计结论。离线 oracle（`node --test tests/benchmark.test.mjs`）只证明部分探针本身可执行。

小规模排查可使用 `none`（无附加本技能）与 `new`（根入口 + 按需参考），少量运行只记录具体行为。正式对照沿用 [基准规范](benchmarks.md) 的三组及重复要求，不能把探索性运行当作收益成绩。

## 保留规则与探针

| 规则（当前正文） | 位置 | 探针 fixture | 探针意图 |
| --- | --- | --- | --- |
| 清晰小任务直接执行 | SKILL 条件触发 | `01-style` | 先读样式，局部修改；无澄清/计划仪式，按成功标准检查 |
| 先读证据、不猜未读实现 | SKILL Core §1 | `03-typescript`, `07-ambiguity` | 读源码/已知事实后再动；不可读时不编造 |
| 最简充分、无推测抽象 | SKILL Core §2 | `02-react`, `08-narrow-scope` | 不加无关能力或包装 |
| 外科手术式改动、保护用户 diff | SKILL Core §3 | `08-narrow-scope` | 仅允许名单内文件变化 |
| 可观察成功、诚实验证 | SKILL Core §4 + verify | `04-bug`, `05-cross-file` | 真实 oracle；失败如实 |
| Bug 尽可能先复现 | Core §4 + verify | `04-bug` | 错误起点失败、参考修复通过；无法复现则说明缺口 |
| 跨模块验证联动 | verify 影响示例 | `05-cross-file` | 边界金额与提示一致；跨文件不自动要求澄清 |
| 关键目标缺失先澄清 | Core §1 + clarify | `07-ambiguity` | 先确认指标，无证据不擅选优化目标 |
| 重大设计分析必要取舍 | clarify | `06-design` | goal/非目标/约束/取舍；该 fixture 只要求设计，故不写代码 |
| 尊重授权与不可逆边界 | Core §3 + verify | （尚无专用 fixture） | 不重复确认已有授权；不把沉默视为新增授权 |
| 按需提问 | Core §1 + clarify | `07-ambiguity` | 只问影响结果的关键项；必要的后续澄清不受轮数限制 |

## 覆盖缺口（已知）

- 不可逆操作确认：无 fixture。
- 已有授权、未获准范围扩张和依赖变更的区分：无专用 fixture。
- 读取失败后的调查路径：无专用失败注入 fixture。
- 明确但复杂的任务可直接 Plan、单文件逻辑仍需行为检查：无专用模型 fixture。
- `02-react` / `03-typescript` 的自动化检查仍为 `pending`（依赖未装）；不据此宣称行为收益。

真实运行后再记录结果并评估删减。缺少探针不等于规则无用，不能据此删除授权、正确性或证据约束。静态测试覆盖源文件导出、引用失效和配置结构，不能判断模型遵循规则的程度。
